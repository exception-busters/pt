# 진행 현황 정리 (2025-02-15)

## 1. 현재까지 수행한 작업
- 문서 통합 요약 업데이트: 제안서/요구사항/설계 명세 핵심을 `문서/문서_요약.md`에 반영하고 API 계약·데이터 스키마·AI 규칙 등을 보강했습니다.
- README 정비: 프로젝트 소개, 실행 절차, 계획된 구조 및 기술 스택을 추가했습니다.
- 코드 구조 리팩터링 1단계: `lib/features/**/presentation` 폴더로 화면을 분리하고 `main.dart`는 테마/엔트리만 담당하도록 정리했습니다.
- GoRouter + Riverpod 도입: 인증 상태 기반 라우팅, ShellRoute로 탭 구조 구성, 딥링크/서브라우트 뼈대와 404 에러 화면을 추가했습니다.
- 딥링크용 예시 화면: `/app/workout/detail/:id`, `/app/records/detail/:id` 경로를 추가하고 목록/홈 카드에서 해당 경로로 이동하도록 구성했습니다.

## 2. 남아있는 이슈 및 즉시 수정 필요 항목
- 딥링크 복귀 버그: `flutter run --route=/app/workout/detail/cardio` 실행 후 로그인하면 `/app/home`으로 이동합니다. 로그인 전에 요청한 경로를 복귀시키는 로직이 기대대로 작동하지 않아 추가 디버깅이 필요합니다.
- AuthController 상태 흐름 점검: `_pendingRedirect` 저장/복원 로직과 GoRouter `redirect` 함수가 올바르게 상호작용하는지 확인해야 합니다.
- Router 초기 경로 처리: `MaterialApp.router`의 초기 경로 처리와 Windows 빌드에서 `--route` 전달 여부를 다시 검증해야 합니다.

## 3. 향후 진행 계획
### 3.1 단기 (딥링크 문제 해결)
- 로그인 성공 시점의 리다이렉트 조건을 재조정하여 `state.uri`와 저장된 경로의 충돌 여부를 분석합니다.
- 로그인 성공 후 `context.go` 호출 여부를 다시 검토하거나, `GoRouter`의 `refresh()` 활용 가능성을 검토합니다.
- `WidgetsBinding.instance.platformDispatcher.defaultRouteName` 값을 플랫폼별로 로깅하고 전달 경로를 확인합니다.

### 3.2 중기 (기능 확장)
- 네트워크 계층 스켈레톤: `dio` + JWT 인터셉터, `flutter_secure_storage` 적용.
- 상태 분리: auth/profile/workout/nutrition 등 Riverpod Provider를 세분화하고 목업 데이터를 정리합니다.
- 테스트/품질: `flutter analyze`, 단위 테스트, 린트 규칙 확장을 진행합니다.

### 3.3 장기 (MVP 개발)
- 서버 연동 및 실제 API 계약 구현.
- MediaPipe/TFLite 연동, 실시간 자세 분석 로직 완성.
- 데이터 영속화(로컬 캐시/오프라인), 그래프/통계 UI 강화.
