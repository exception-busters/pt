# 식단 데이터 Supabase 동기화 수정 가이드

## 📋 문제 요약

**증상**: 새 기기에서 로그인했을 때 식단 기록이 표시되지 않음

**원인**:
1. 데이터베이스 스키마(`usermeal` 테이블)와 애플리케이션 코드 간의 불일치
2. 저장 로직이 필요한 데이터를 제대로 저장하지 않음
3. 불러오기 로직이 존재하지 않는 컬럼을 읽으려고 시도함

## 🔧 해결 방법

### 1단계: Supabase에 새 테이블 생성 (필수!)

**파일 위치**: `문서/meal_tables_migration.sql`

**실행 방법**:
1. Supabase 대시보드 접속
2. SQL Editor 메뉴로 이동
3. `meal_tables_migration.sql` 파일의 내용을 복사
4. SQL Editor에 붙여넣기
5. **RUN** 버튼 클릭하여 실행

**생성되는 테이블**:
- `meal_record`: 식단 기록 메인 테이블 (날짜, 끼니 종류, 총 영양소)
- `meal_component`: 식단 구성요소 테이블 (각 음식의 상세 정보)

**주요 기능**:
- RLS (Row Level Security) 활성화 - 사용자는 자신의 데이터만 접근
- 인덱스 생성 - 빠른 데이터 조회
- 자동 업데이트 시간 트리거

### 2단계: 애플리케이션 코드 수정 (완료됨)

#### ✅ 수정된 파일 1: `lib/features/diet/application/diet_providers.dart`

**변경 내용**:
- `_syncMealToSupabase` 메서드를 새 테이블 구조에 맞게 수정
- `meal_record` 테이블에 메인 식단 정보 저장
- `meal_component` 테이블에 각 음식의 상세 정보 저장
- 상세한 로그 추가

**주요 기능**:
```dart
// 저장 흐름:
1. 기존 기록 삭제 (같은 날짜, 같은 끼니)
2. meal_record에 식단 메인 정보 삽입
3. meal_component에 음식 구성요소들 삽입
4. 성공/실패 로그 출력
```

#### ✅ 수정된 파일 2: `lib/features/records/data/diet_history_repository.dart`

**변경 내용**:
- `_loadFromSupabase` 메서드를 새 테이블 구조에 맞게 수정
- `meal_record`와 `meal_component` 테이블에서 데이터 조회
- 두 테이블의 데이터를 조인하여 완전한 식단 기록 구성

**주요 기능**:
```dart
// 불러오기 흐름:
1. meal_record에서 식단 기록 조회
2. meal_component에서 구성요소 조회
3. meal_record_id로 두 테이블 조인
4. 날짜별로 그룹화하여 DailyRecord 생성
```

## ⚠️ 주의사항

### 1. Supabase 마이그레이션은 필수입니다!
코드만 수정하고 Supabase에 테이블을 생성하지 않으면 앱이 작동하지 않습니다.

**에러 메시지 예시**:
```
❌ [Diet Sync] Supabase 동기화 실패: relation "meal_record" does not exist
```

이 에러가 나타나면 → Supabase에서 SQL 마이그레이션을 실행하세요!

### 2. 기존 데이터는 자동으로 이전되지 않습니다
- 기존 `usermeal` 테이블의 데이터는 새 테이블로 자동 이전되지 않습니다
- 기존 데이터는 SharedPreferences (로컬 캐시)에 남아있어 같은 기기에서는 계속 보입니다
- 필요하다면 별도로 데이터 마이그레이션 스크립트를 작성해야 합니다

### 3. RLS (Row Level Security) 정책
- 새 테이블에는 RLS가 활성화되어 있습니다
- 사용자는 자신의 데이터만 읽고 쓸 수 있습니다
- 로그인하지 않은 상태에서는 데이터 접근 불가

## 🔍 트러블슈팅

### 문제 1: "relation does not exist" 에러
**원인**: Supabase에 테이블이 생성되지 않음
**해결**: `meal_tables_migration.sql` 파일을 Supabase SQL Editor에서 실행

### 문제 2: 식단이 저장되지 않음
**확인 사항**:
1. 로그인 상태 확인
2. 로그에 `🎉 [Diet Sync] Supabase 동기화 성공` 메시지 있는지 확인
3. Supabase 대시보드에서 `meal_record` 테이블 데이터 확인

### 문제 3: 식단이 불러와지지 않음
**확인 사항**:
1. Supabase 대시보드에서 `meal_record` 테이블에 데이터가 있는지 확인
2. 로그에 `📡 [Diet] Supabase meal_record 응답: X개 기록` 메시지 확인
3. RLS 정책이 올바르게 설정되어 있는지 확인

### 문제 4: RLS 정책 에러
**원인**: Row Level Security 정책 문제
**해결**: Supabase 대시보드에서 Authentication → Users에서 로그인한 사용자의 UUID 확인
