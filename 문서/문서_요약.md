# 요구사항 정의 및 분석 명세서 핵심 정리
- 문제 정의: 고가 PT, 잘못된 자세, 동기 부족 등을 해결하기 위해 AI 기반 모바일 PT 앱을 제안.
- 목표 및 주 기능: 실시간 자세 인식·피드백, 맞춤 루틴 생성, 식단 분석, 기록 시각화로 동기 부여 강화.
- 비즈니스 지표: 일간 활성 사용자 5천 명, 자세 교정 만족도 80% 이상, 3개월 목표 달성률 60% 이상.
- 시스템 범위: Flutter 모바일 앱, API 서버(Spring/Node), AI 추론 서버(TFLite/MediaPipe), PostgreSQL DB.
- 기능 요구사항(FR-001~009): 프로필 설정, 개인화 루틴, 카메라 인식·피드백, 식단 관리, 목표/기록 시각화, 알림, 커뮤니티, 개인화 엔진.
- 비기능 요구사항: 실시간성(지연 ≤1초, FPS≥15), API 응답≤500ms, 보안(TLS1.2, SHA-256+Salt, AES-256), 가용성 99%.
- 데이터 관리: User/Routine/WorkoutLog/Meal/Feedback 주요 테이블, 영상 30일 내 삭제, 기록 2년 보관.
- 테스트/보안: 단위~사용자 테스트, JWT 인증·권한 분리, 영상 블러 처리.
- 프로젝트 관리: 폭포수 기반 단계 진행, 9~12월 일정, 역할 분담(PM+QA, AI+서버, 앱 개발), 월 1회 업데이트.

# 제안서 핵심 정리
- 제안 배경: 홈트 시장 성장, 온라인 영상 한계 보완 필요; 비대면 시대 맞춤 PT 요구.
- 주요 목표: 실시간 자세 분석 5종 운동, 식단 기록/분석, 전문가 프로그램 상점, 챌린지·랭킹 도입.
- 차별점 분석: PT쌤·플랜핏 대비 모션 캡처, 식단·상점 통합, 게이미피케이션 강조.
- 시스템 아키텍처: 모놀리식 3계층 + 분리된 AI 추론 서버; Flutter 클라이언트, Spring Boot 백엔드, PostgreSQL/Firebase Auth, MediaPipe Pose.
- 개발 방법: 폭포수 기반 문서화 + 2주 스프린트 보조; Docker 환경 통일.
- 기능 범위: 요구사항 문서와 동일 FR-001~FR-009에 우선순위 지정, MVP 초점.
- 비기능 범위: 실시간 분석 FPS≥15, 처리 지연≤800ms, 보안 정책(TLS, SHA-256, AES-256) 명시.
- 구현 방안:
  - 모션 캡처 파이프라인: Flutter camera → MediaPipe Pose(33 랜드마크) → API 전송 → 코사인 유사도 평가 → TTS/텍스트 피드백.
  - 식단 관리: Food DB 기반 영양 분석, 운동 기록 연동, 부족 영양소 추천.
  - 운동 콘텐츠 상점: 기본 무료 + 프리미엄 인앱 구매, USER_CONTENT_ACCESS 권한 관리.
  - 커뮤니티/게이미피케이션: 챌린지, 랭킹, 뱃지로 동기부여.
- 테스트/관리: 폭포수 단계별 산출물, 역할 분담, 일정, 게이미피케이션을 통한 유지 전략.

# 프로젝트 설계 명세서 핵심 정리
- 목표: AI 자세 분석, 자동 기록, 맞춤 루틴/식단, 커뮤니티까지 포괄하는 개인 맞춤 피트니스 앱 설계.
- 환경: 서버 Ubuntu+Node/PostgreSQL, 클라이언트 Flutter, AI TFLite+MediaPipe, Firebase Auth, AWS S3.
- 3계층 구조: Presentation(Flutter), Business(서비스·AI 분석), Data(PostgreSQL/S3) 분리.
- 주요 모듈 11개:
  1. UserManager(회원·프로필)
  2. WorkoutManager(운동 세션·기록)
  3. AIAnalyzer(자세 피드백)
  4. RoutineService(루틴 생성/추천)
  5. NutritionService(식단/영양)
  6. GoalTracker(챌린지·랭킹·뱃지)
  7. Store(콘텐츠 구매)
  8. NotificationManager(푸시 알림)
  9. ReportGenerator(통계 리포트)
  10. DBConnector(DB 접근 추상화)
  11. AdminModule(운영자 도구)
- 데이터베이스 설계: User, UserProfile, Exercise 등 상세 필드 정의; 영상/자세 데이터 S3 저장 계획.
- 서비스 흐름: 실시간 영상 캡처→AI 분석→피드백→기록 저장→목표/통계/커뮤니티 연계.
- 제약 및 참고: 실시간 AI 성능 고려해 TFLite 경량화, Flutter로 iOS/Android 동시 지원, 개인정보 보호 기준 준수.

(※ 향후 기능 구현 시 이 요약을 참고해 요구사항 맵핑, 모듈 간 인터페이스, 비기능 목표를 빠르게 확인할 수 있습니다.)
