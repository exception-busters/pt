# 요구사항 정의 및 분석 명세서 핵심 정리
- 문제 정의: 고가 PT, 잘못된 자세, 동기 부족 등을 해결하기 위한 AI 기반 모바일 PT 앱.
- 1차 목표 및 핵심 기능: 실시간 자세 인식·피드백, 맞춤 루틴 생성, 식단 분석/기록, 운동·식단 기록 시각화.
- 후속(2차) 기능: 커뮤니티 챌린지·랭킹·뱃지, 알림 고도화 등은 초기 MVP 이후 단계에서 확장.
- 비즈니스 지표: 일간 활성 사용자 5천 명, 자세 교정 만족도 80% 이상, 3개월 목표 달성률 60% 이상.
- 시스템 범위: Flutter 모바일 앱, API 서버(Spring/Node), AI 추론 서버(TFLite/MediaPipe), PostgreSQL DB.
- 기능 요구사항(FR-001~009): 프로필 설정 → 개인화 루틴 → 카메라 인식·피드백 → 식단 관리 → 목표/기록 시각화가 MVP 핵심. 알림·커뮤니티·개인화 엔진은 2차 배포로 분리.
- 비기능 요구사항: 실시간성(지연 ≤1초, FPS≥15), API 응답≤500ms, 보안(TLS1.2, SHA-256+Salt, AES-256), 가용성 99%.
- 데이터 관리: User/Routine/WorkoutLog/Meal/Feedback 주요 테이블, 영상 30일 내 삭제, 기록 2년 보관.
- 테스트/보안: 단위~사용자 테스트, JWT 기반 인증·권한 분리, 영상 블러 처리.
- 프로젝트 관리: 폭포수 기반 단계 진행, 9~12월 일정, 역할 분담(PM+QA, AI+서버, 앱 개발), 월 1회 업데이트.

# 제안서 핵심 정리 (MVP 우선순위 반영)
- 제안 배경: 홈트 시장 성장, 온라인 영상 한계 보완 필요; 비대면 시대 맞춤 PT 요구.
- MVP 목표: (1) 실시간 자세 분석 5종 운동, (2) AI 기반 식단 기록/추천, (3) 운동·식단 기록 통합 관리.
- 후속 목표: 챌린지·랭킹·뱃지 등 게이미피케이션, 전문가 프로그램 상점, 커뮤니티 강화를 2차 로드맵으로 배치.
- 차별점: 모션 캡처 기반 자세 교정 + 식단/운동 통합 관리, 추후 커뮤니티·상점 확장 가능.
- 아키텍처: 모놀리식 3계층 + 분리된 AI 추론 서버; Flutter 클라이언트, Spring Boot 백엔드, PostgreSQL/Firebase Auth, MediaPipe Pose.
- 개발 방법: 폭포수 기반 문서화 + 2주 스프린트 보조; Docker로 환경 통일.
- 기능 범위: MVP는 FR-001~FR-006, FR-009 중심 (프로필~식단/기록·개인화). FR-007~FR-008(알림·커뮤니티)는 후속.
- 비기능 범위: 실시간 분석 FPS≥15, 처리 지연≤800ms, 보안 정책(TLS, SHA-256, AES-256) 명시.
- 구현 방안:
  - 모션 캡처 파이프라인(MVP 핵심): Flutter camera → MediaPipe Pose(33 랜드마크) → API 전송 → 코사인 유사도 평가 → TTS/텍스트 피드백.
  - 식단 관리(MVP 핵심): Food DB 기반 영양 분석, 운동 기록 연동, 부족 영양소 실시간 추천.
  - 운동 콘텐츠 상점·커뮤니티: 후속 배포 시 활성화 예정.
- 테스트/관리: 폭포수 단계별 산출물, 역할 분담, MVP 우선 개발 후 확장.

# 프로젝트 설계 명세서 핵심 정리
- 목표: AI 자세 분석과 자동 기록, 맞춤 루틴/식단까지 포함한 개인 맞춤 피트니스 앱 설계.
- 환경: 서버 Ubuntu+Node/PostgreSQL, 클라이언트 Flutter, AI TFLite+MediaPipe, Firebase Auth, AWS S3.
- 3계층 구조: Presentation(Flutter), Business(서비스·AI 분석), Data(PostgreSQL/S3) 분리.
- MVP 초점 모듈:
  1. UserManager(회원·프로필)
  2. WorkoutManager(운동 세션·기록)
  3. AIAnalyzer(자세 피드백)
  4. RoutineService(루틴 생성/추천)
  5. NutritionService(식단/영양)
  6. ReportGenerator(통합 기록/리포트)
  7. DBConnector(Data access)
- 후속 모듈(2차): GoalTracker(챌린지·랭킹·뱃지), Store(콘텐츠 구매), NotificationManager(푸시), AdminModule(운영자 도구) 등을 순차 확장.
- 데이터베이스 설계: User/UserProfile/Exercise 등 컬럼 정의, 영상·자세 데이터 S3 저장 계획, 영상 30일 내 삭제 정책.
- 서비스 흐름: 실시간 영상 캡처→AI 분석→피드백→기록 저장→식단/운동 데이터 결합 통계→추후 커뮤니티/보상 연계.
- 제약 및 참고: TFLite 경량화로 실시간 성능 확보, Flutter로 iOS/Android 동시 지원, 개인정보 보호 기준 준수.

(※ 이 요약본은 MVP 범위와 후속 로드맵을 명확히 구분하여 구현 우선순위를 빠르게 파악할 수 있도록 정리했습니다.)
