# 문서 요약 (단일 파일로 프로젝트 파악 가능하도록 재정리)

이 문서는 제안서, 요구사항 정의 및 분석 명세서, 프로젝트 설계 명세서의 핵심을 통합 요약한 것이다. 본 문서만으로 프로젝트 성격, 범위, 아키텍처, 우선순위, 지표, 향후 계획을 이해하고 이어서 작업할 수 있도록 구성했다.

## 1. 프로젝트 개요
- 문제 정의: 고가의 PT 비용, 잘못된 자세로 인한 부상 위험, 동기 부족, 개인화 부족(정적 영상)의 한계를 해결하기 위한 AI 기반 모바일 PT 앱.
- 목표: 스마트폰 카메라와 AI로 실시간 자세 인식/피드백을 제공하고, 맞춤 운동 루틴과 식단 관리, 기록 시각화를 통합 제공.
- 핵심 가치: 실시간 자세 교정 정확도, 개인화 루틴/식단 추천, 사용성(동기 부여), 확장성(커뮤니티/상점/알림).

## 2. 범위 및 우선순위
- MVP(1차) 범위
  - 회원/프로필: 가입/로그인, 기본 프로필(키/몸무게/목표/레벨)
  - 실시간 자세 분석: 5종 운동(예: 스쿼트, 런지 등)에 대한 포즈 랜드마크 분석과 텍스트 피드백, 반복 카운트(간단 기준)
  - 운동 루틴: 목표/레벨 기반 자동 추천(룰 기반 초기 버전), 루틴 관리
  - 식단 기록/분석: 텍스트/사진 입력(초기엔 텍스트 중심), 칼로리/영양소 기본 분석
  - 기록/리포트: 운동/식단 기록 저장 및 통계/시각화(일/주 단위)
- 2차(후속) 범위
  - 알림 고도화(푸시), 챌린지·랭킹·뱃지(게이미피케이션)
  - 전문가 프로그램 상점(콘텐츠 구매), 관리도구(Admin)
  - 적응형 추천 고도화(모델/규칙), HealthKit/Google Fit 연동

## 3. 성공 지표(초기 가이드)
- DAU 5,000 이상(3~6개월), 자세 교정 만족도 ≥ 80%
- 3개월 목표 달성률 ≥ 60%, 세션 유지율/재방문율 개선
- 실시간 처리 성능: 분석 지연 ≤ 800~1000ms, FPS ≥ 15

## 4. 아키텍처 개요
- 구조: 3-Tier(프론트/서비스/데이터) + 분리된 AI 추론 서버
- 클라이언트: Flutter(Dart), Android 10+/iOS 14+, 웹/데스크톱 호환
- 서버: Node.js(또는 Spring Boot), REST API, PostgreSQL
- AI: TensorFlow Lite + MediaPipe Pose(33 랜드마크), On-device 우선, 필요 시 경량 서버 추론
- 인증/저장소: Firebase Auth(JWT), AWS S3(영상/이미지), TLS 1.2+

## 5. 핵심 모듈(요약)
- UserManager: 회원/인증/프로필. 엔드포인트 예) POST /auth/signup, /auth/signin, GET/PUT /users/me. JWT 발급/검증.
- WorkoutManager: 운동 세션 제어(READY/RUNNING/PAUSED/FINISHED), 기록 저장, 난이도 조절(간단 룰), WebSocket 이벤트 가능.
- AIAnalyzer: 포즈 좌표(33개 랜드마크) 입력 → 자세 정확도/반복수 추정 → 피드백 텍스트/스코어 반환. 엔드포인트 예) POST /analyze.
- RoutineService: 목표/레벨/최근 수행 데이터 기반 개인화 루틴 생성/추천(룰 기반→고도화 예정).
- NutritionService: 식단 기록/영양 분석, 목표 대비 부족 영양소 추천.
- ReportGenerator: 일/주/월 통계 및 리포트 생성.
- DBConnector: 데이터 접근 표준화, 트랜잭션/쿼리 관리.
- 후속 모듈: GoalTracker(챌린지/랭킹/뱃지), Store(유료 콘텐츠), NotificationManager(푸시), AdminModule(운영 도구).

## 6. 데이터 개요(논리)
- 주요 엔티티: User, UserProfile, Exercise, WorkoutSession, ExerciseRecord, Routine, Meal, MealItem, Feedback
- 보관/삭제: 원본 영상 30일 이내 자동 삭제, 기록 데이터 2년 보관(정책 조정 가능)

## 7. 인터페이스(예시)
- Auth: POST /auth/signup, POST /auth/signin, GET /users/me, PUT /users/me (JWT)
- Workout: POST /workouts/start, GET /workouts/stream(WebSocket), POST /workouts/record
- AI: POST /analyze (PoseDataDto: 프레임별 33 랜드마크 좌표)
- Nutrition: POST /meals, GET /meals?range=..., GET /reports/daily|weekly

## 8. 비기능 요구사항
- 성능: 실시간성(지연 ≤ 800~1000ms, FPS ≥ 15), API 응답 ≤ 500ms(평균)
- 보안/개인정보: TLS 1.2+, 비밀번호 SHA-256+Salt, 민감 데이터 AES-256, 토큰 만료/갱신, 영상 블러/가림 처리
- 가용성/안정성: 99% 이상(초기), 로그/모니터링/경보 체계 기본 구축

## 9. 제약/가정
- 저사양 기기 대응(최소 사양 정의, 모델 경량화), 모바일 네트워크 품질 편차
- iOS/Android 권한 정책 차이 및 스토어 심사 기준 준수 필요
- 초기엔 룰 기반 추천(개인화 엔진은 점진 개선)

## 10. 개발/운영 방법
- 방법론: 문서화 중심 + 2주 스프린트 보조, 이슈/태스크 관리(Jira/GitHub Projects)
- 품질: 단위/위젯/통합 테스트, QA 시나리오, 사용자 테스트(파일럿)
- 배포: Docker 기반 서버 배포, 클라이언트 스토어 제출 파이프라인(베타 채널)

## 11. 현재 앱 구현 현황(Repo 기준 빠른 스냅샷)
- UI 테마/네비: 연두색 파스텔 Material, 탭 5개(홈·식단·운동·기록·프로필)
- 인증 흐름: 로그인/회원가입 화면(목업, 로컬 상태, 서버 미연동)
- 기능 화면: 스낵바로 ‘추후 구현’ 표기된 목업 카드/리스트 구성
- 상태관리/라우팅: `setState` + 기본 Navigator. 서버/API/스토리지 연계 없음

## 12. 단기 실행 계획(MVP 착수 가이드)
- 코드 구조화: features/widgets/services/models/routes 단위로 분리, 라우팅 맵 정리(GoRouter 권장)
- 상태관리: Riverpod/Bloc 택1로 인증/프로필/운동/식단/기록 상태 분리
- API/보안: dio 기반 REST 클라이언트, JWT 보관(`flutter_secure_storage`), 인터셉터/리트라이/토큰갱신
- AI 연동: MediaPipe Pose(온디바이스) → 간단 폼 체크(코사인 유사도 등) → 텍스트 피드백
- 데이터 스키마: User/Profile/Workout/Record/Meal 설계, 마이그레이션/시드 스크립트 준비
- 테스트: 기존 카운터 테스트 정리, 핵심 위젯/서비스 단위 테스트 추가

## 13. 로드맵(요약)
- 0단계: 구조 리팩터(라우팅/상태/서비스 레이어) + 인증/프로필 + 기본 기록
- 1단계(MVP): 5종 운동 자세 분석 + 루틴 추천(룰 기반) + 식단 기록/기초 분석 + 리포트
- 2단계: 알림/챌린지/랭킹/뱃지 + 상점 + 적응형 추천 고도화 + 운영자 도구 + 헬스킷/핏 연동

## 14. 리스크/대응
- 실시간 성능 미달: 모델 경량화(TFLite), 프레임 샘플링, 네이티브 최적화
- 개인정보/규제: 영상 최소 수집·단기 보관, 마스킹/익명화, 동의 고지 강화
- 디바이스 다양성: 핵심 기기 리스트 우선 최적화, 기능 플래그로 단계적 전개

## 15. 요약 문장(엘리베이터 피치)
스마트폰 카메라와 AI로 사용자의 운동 자세를 실시간 교정하고, 개인화된 루틴·식단·기록을 한곳에서 관리하는 지능형 PT 플랫폼. MVP는 5종 운동 자세 분석과 기본 추천/기록/식단을 우선 구현하고, 이후 챌린지/랭킹/상점/알림 등으로 확장한다.
